# ТЗ на MVP: B2B-платформа «NordSea Export» с трекером оптовых запросов

> Сформировано по описанию реального заказа с фриланс-биржи (шаг 2 урока).
> Готового ТЗ у заказчика нет и не будет на старте — процесс заказчика (проектирование → ТЗ → реализация) совпадает с процессом урока.

## 1. Источник заказа

- **Заказ:** «MVP B2B-сайт для экспортной компании (рыба и морепродукты)», бюджет по договоренности.
- **Суть:** не «корпоративный сайт», а рабочий B2B-инструмент для получения и обработки оптовых запросов.
- **Ключевая логика бизнеса:** Запрос → диалог → сделка.
- **Требования заказчика:** B2B-позиционирование, мульти-продуктовый формат, без цен, архитектура с заделом на масштабирование; структура: Главная, Продукция (категории + карточки без цен), Условия сотрудничества, Inquiry-форма B2B-запроса, О компании, Контакты; адаптив; языки EN + RU (CN — архитектурно).

## 2. Цель MVP

1. **Получение запросов:** публичный сайт EN/RU, который представляет компанию и ассортимент (без цен) и собирает качественные оптовые запросы через Inquiry-форму.
2. **Обработка запросов:** внутренний трекер с канбан-доской для менеджера — движение заявки по стадиям «Новый запрос → В диалоге → Переговоры и образцы → Сделка» (плюс «Отказ»), с историей и комментариями.

Трекер — это модуль обработки запросов (то, что заказчик называет «Запрос → диалог → сделка»), а не CRM: без воронок оплаты, без кабинетов, без интеграций.

## 3. Роли пользователей

| Роль | Что делает |
|---|---|
| **Гость** (оптовый покупатель, RU/EN) | Смотрит каталог без цен, читает условия, отправляет B2B-запрос |
| **Менеджер по экспорту** | Авторизуется, работает с канбан-доской: меняет стадии заявок, комментирует, назначает ответственного |
| **Администратор** | Всё, что менеджер, + управление каталогом (добавить/скрыть продукт) и просмотр списка пользователей |

## 4. Экраны

**Публичная часть (EN + RU, адаптив):**
1. Главная — B2B-позиционирование, категории продукции, «как мы работаем» (Запрос → диалог → сделка), CTA.
2. Продукция — категории + карточки без цен (название, латинское название, характеристики, упаковка, минимальная партия, сезон).
3. Условия сотрудничества — модели поставки (FOB/CIF/EXW), минимальные партии, документы, оплата, логистика.
4. Inquiry — форма B2B-запроса с валидацией и подтверждением отправки.
5. О компании. 6. Контакты. 7. Страница 404.

**Админ-часть (RU):**
8. Вход (логин/пароль).
9. Канбан-доска запросов — колонки стадий, карточки, drag&drop, счётчики, поиск.
10. Карточка запроса (модальное окно) — данные клиента, история стадий, комментарии, ответственный.
11. Управление продукцией (только админ) — добавить/скрыть продукт.

## 5. Функции MVP

- Переключатель языков EN/RU (словари в отдельных файлах — добавление CN = один новый словарь).
- Каталог по категориям, карточки без цен; кнопка «Запросить условия» уводит в форму с предвыбранным продуктом.
- Форма запроса с валидацией; заявка сохраняется и появляется в трекере в колонке «Новый запрос».
- Канбан: drag&drop карточек между колонками, фиксация каждой смены стадии в истории (кто/когда/из какой в какую).
- Комментарии менеджеров в карточке заявки; поле «Ответственный».
- Авторизация по логину/паролю (сессия в HttpOnly-cookie); доступ к доске только после входа.
- Роли: менеджер не имеет доступа к управлению каталогом; гость не имеет доступа к API заявок.
- Админ: добавление/скрытие продуктов каталога.
- Адаптивная вёрстка (мобильные/планшет/десктоп).
- Лёгкая защита формы от спама (лимит запросов с одного IP).

## 6. Архитектура и задел на масштабирование

- **Стек:** Node.js + Express, фронт — чистые HTML/CSS/JS без сборки, хранение — JSON-файлы с атомарной записью.
- REST API (JSON), отдельные модули: хранилище (`lib/store.js`), авторизация (`lib/auth.js`), маршруты.
- Хранилище JSON → при росте заменяется на PostgreSQL без переписывания маршрутов (одинаковый интерфейс).
- i18n-словари отдельными файлами (+CN — новый словарь, без изменения кода).
- Роли — основа для будущих личных кабинетов покупателей.
- В заказе указан WordPress; для MVP строим лёгкое кастомное решение с публикацией на Railway (по схеме урока): быстрее получить работающий инструмент и показать архитектуру. Контент переносим на WordPress на этапе масштабирования, если потребует заказчик.

## 7. Критерии готовности MVP

1. Сайт открывается по HTTPS-ссылке, языки EN+RU, вёрстка адаптивна.
2. Гость находит продукцию без цен и отправляет запрос; получает подтверждение.
3. Заявка с формы появляется на канбан-доске в колонке «Новый запрос».
4. Менеджер входит по логину/паролю, перемещает карточки между стадиями, история и комментарии сохраняются.
5. Без авторизации доступ к доске и API заявок закрыт; менеджеру недоступно управление каталогом.
6. Админ добавляет/скрывает продукт — каталог обновляется.
7. Код опубликован на GitHub, проект задеплоен на Railway, публичная ссылка проверена в режиме инкогнито.

**Не входит в MVP (по заказу):** интернет-магазин, онлайн-оплата, личные кабинеты, CRM, SEO-прокачка, цены на сайте.

## 8. Дизайн

Брендбука у клиента нет → аккуратный нейтральный стиль (см. `info/brandbook.md`): глубокий синий + ледяной белый, деловая типографика Inter, логотип `info/logo.svg` (текстовый знак, легко заменить на фирменный). Тон: надёжный экспортёр, «свежесть и холод», без цен — «Price on request».

## 9. Допущения и открытые вопросы клиенту

1. Название компании в заказе не указано → рабочее «NordSea Export» (замена — 1 файл словаря).
2. Ассортимент не передан → демо-каталог: 3 категории, 9 продуктов (замена на реальные данные — правка одного JSON).
3. Вопросы клиенту: актуальный список продукции и фото? Какие порты отгрузки и Incoterms? Нужен ли CN на старте или в следующей итерации? Кто заводит/модерирует менеджеров? Есть ли фирменный стиль/домен .com?
